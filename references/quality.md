# 验收与交付

技术工具只检查实际输出，不生成虚假的功能/视觉/用户认可。

1. 功能因果：首次指令、前后状态、来源、成果与宣称一致；演员模拟范围清楚，关键动作和保存/批准结果有断言。
2. 原生保真：版本、组件来源、页面/布局/交互/点击反馈与动效有对照；特殊平台/语言独立验证。
3. 手机可读性：320/430px观看下关键文字清楚、组件与作品完整、字幕不遮挡，鼠标不越界，字体比例真实。
4. 连续运动与节奏：操作前镜头落稳，过程中不漂移，连续帧无异常闪烁/跳变；逐镜理由与停顿用途成立，正常速度看完整片。
5. 声音：最终可见事件与键鼠声同步、音乐单层、跨片变化、无削波或不明断音；记录实际听审情况。
6. 文件：默认3840×2880、60fps、48kHz立体声、完整解码；实际总帧数、时长、sha256与时间线吻合。
7. 交付：中英各自完整影片及证据、X和小红书文案、源工程和实际承诺的成果。发送状态与制作状态分开。

参考模板 `acceptance.json`。技术、静帧、整片观看、听审、用户定版分开记录，未做填pending，不把校准影片通过当成产品成片通过。适用必检项没有证据时进待处理。首次检查后最多2轮自动返修，按最小必要范围处理，未解阻断项不能靠平均分抵消。

归档清单声明影片真实路径、3840×2880/60fps、双平台文案和验收记录；旧片明确保留16:9时可声明3840×2160，不能自动由文件尺寸推导例外。所有检查证据必须存在并绑定本版影片sha256，归档器执行完整解码。

`archive_delivery.py` 保留旧版与发送状态，重复事件幂等；合格进入本工程deliveries/01_可选成片，不完整进入02_待处理。这个目录不是自动发布队列。旧视频不自动迁移，不创建系统调度。

正常完成后 Agent 在本地 `library/entries.jsonl` 追加案例id、版本、语言、摘要、输出相对路径、sha256、验收状态和后续决定。已对接接收者的素材库时按其原生接口登记，同一个案例不要双写出两个相互冲突的状态源。
