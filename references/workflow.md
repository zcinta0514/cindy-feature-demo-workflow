# 从需求到交付

## 选题与事实

选题兼顾组件/特色功能和用户任务/工作流两类，以开发者或深度使用者能理解的能力为重点，不要求每条写代码。任务要有可视化证据：操作、变化、最终可核对成果。优先网页、游戏、看板和完整组件，少用长聊天与密集小字；在320–430px观看宽度下检查，不能靠极端放大补救选题。

先查目标版本真实入口、必要前提、状态变化和权限边界。`assets/manifest.json` 的源码提交只是品牌/基线来源，不冒充当前最新产品。用接收者可用的 GitHub 插件读取源码/提交，必要时在独立工程获取对应仓库；固定版本后再适配，不复制发送者的工作树。案例库可选，有库则查询用户指定案例；无库从任务设计开始，不要求迁移历史台账。

## 脚本

Agent 填写 `production-script.json`：需求、产品依据、资源、自然对白、操作依赖、前后状态、原生组件、镜头、字幕、声音、检查与交付。模板空值表示 draft，不能直接宣布可渲染。用户只要脚本/HTML时停止在相应阶段，通常的实际制作自行自审推进；只有用户要求审稿才等具体脚本确认。

每个关键操作说明观众应看到什么变化；片中输入像真实工作，不夹带摄影、字幕或卡拍要求。可精炼内容密度并改善原生可视化，但保留功能事实、来源、因果和必要结论。若承诺一个网页/文件，必须实际生成并打开验证，不用结果文字冒充产物。

## 原生组件与缺口补齐

优先用真实源码组件、词条、主题、图标、布局约束和事件，建立隔离 HTML 重演宿主。组件装载成功还不够：定位实际消费入口、状态流、Portal、菜单、编辑保存、键盘焦点和点击反馈，补齐最小完整操作，记录版本和差异。只有有依据的轻微流畅度优化才可变更原生动画；镜头放大不能改产品字号。

没有现成模板时，Agent 继续适配需要的组件/UI/系统页面；缺真实资料、权限或环境时报告具体缺口。移动设备同样复用原生依据，注意机身/安全区、方向、键盘、系统弹层和设备身份；手机框架不能冒充真实设备连接链。原生采集用于对照，默认正文仍为可控时钟的组件重演。

新版本或新平台只核对受影响组件及依赖，不能每片盲目升级软件；语言变化建立独立变体。已有项目不要覆盖，输出指向本片独立目录。

## 包装、镜头和声音

按 [camera.md](camera.md) 构图，按 [runtime.md](runtime.md) 接演员与统一时钟。复用随包品牌资源，正文可扩展，品牌标题按本片文本实测居中，整组上下留白均衡。字幕为独立解释层，讲能力/机制，不逐条复述业务；4K下约72px起并按手机效果实测，单行少字、独立留白、不遮来源或操作目标。

保留首次完整指令与操作因果。Fork 后直接在新会话发送首条指令；普通 Fork 无自动回报，协作通信按实际机制展示。计划模式不能只展示生成结果，按主线覆盖编辑/自动保存、反馈修订、批准当前版本及结果验证；不要为了按钮覆盖破坏主线。

轻快lo-fi/轻电子，100–120 BPM参考范围，跨片更换曲目或有实质变化的原创编配。单层主音乐、独立键盘/点击事件，无鼠标移动声；首尾不叠虚构键鼠声。先保证操作和阅读，再用自然衔接卡新操作段拍点；键声对应最终可见事件。曲库许可在使用时核对，原创保留生成方式和参数。

## 双语

英文和中文同批交付，独立源目录/时间线/事件表/检查记录。改原生 locale、UI词条、用户输入、结果、字幕和首尾，不只翻译表层标题；控件选择器优先稳定标识或本地化词条。中文按完整句子分配输入与阅读时间，不因字符少而闪现；字体实际加载后再测量。两版机制与成果一致，必要的时序差异记录，不复用英文音效位置或验收数值。

## 检查与归档

按 [quality.md](quality.md) 分别记录技术、静帧、连续运动、整片观看、人耳检查及用户定版。首次检查后最多2轮自动返修，按问题最小范围处理，未解阻断项留待处理；不新增日常逐片人工审批。

双平台文案以本片实际展示能力为依据。X简洁、官方产品语气，说明操作与价值，避免夸大自主能力；小红书提供多标题候选和可读的使用场景/步骤，不超出视频事实。平台当前发布限制需要发布时再核对，不把旧字符数当永久标准。

最终归档保留本版摘要、脚本、源场景、音源依据、影片及文案。本地栏目登记不等于已发布，发布与发送另获授权。共享工作流修改、单片修订、单素材修订分别记录；同事安装不继承发送者的调度、账号或素材库权限。
