# 手机可读镜头与节奏

默认最终4:3、3840×2880、60fps。可以用1440×1080逻辑画布；原生产品在独立坐标系中等比缩放，不横向拉伸。原品牌包装采用1920×1080设计坐标，并以中部1440宽的取景窗口呈现，与已确认样片相同；适配正文时必须检查完整控件、字幕和鼠标是否在取景范围。

1. 开场先完整展示位置关系，再按需要聚焦。输入、组件编辑、重要选择框、结果都可推进；已经清楚或需要全局关系时保留全景。
2. 组件展示按整个外边界取景，包含标题、选项、来源与相关反馈；网页/作品以整体布局为主，别为一处指标或文件名切碎画面。
3. 根据真实边界、必要上下文、鼠标完整外形和安全留白计算中心与倍率，不固定套用某个倍数或近景次数。组件占满画幅后不要继续放大。
4. 同区域连续事件共用稳定镜头，减少推近/退回。跨区域先建立足够上下文，避免高倍率长距离平移。缓入缓出参考 Screen Studio 的视觉逻辑，不声称复刻其内部参数。
5. 先对准并落稳，再点击、输入、选择、编辑、拖动和阅读。反馈实际出现后才考虑强调；不追逐每个字符、鼠标或刷新后的数字。
6. Portal、菜单、工具栏、iframe和正文用同一等比变换。鼠标可从约1.9倍视觉尺寸起调，使用者看到的热点与实际点击位置一致，始终置顶。推进/退出锚定同一个真实位置；不要把漂出画面的鼠标简单钳制回边缘而造成假落点。
7. 大鼠标不遮目标，完整外形纳入取景。鼠标到iframe的坐标要经过子页面、父frame、产品相机、最终视口四层换算。

`assets/runtime/camera.mjs` 提供完整边界拟合、平滑插值和坐标转换的纯函数，返回需要整体缩小时应使用的比例，不强迫最低1倍造成裁切。它不替代按实际 UI 选择镜头的判断，也不自动控制原生 Portal。

每个镜头记录推进理由、目标、完整边界、倍率/中心、落稳和锁定操作区间；每个停留记录就绪、输入、反馈、阅读或对照用途。删除无信息暂停、重复鼠标绕行和相邻重复等待；落稳已消耗的阅读时间不再重复累计。状态就绪用条件等待，超时是异常上限，不是固定空等。

保留关键因果与最低阅读时间，不靠统一加速或一闪而过提速。节奏变更后重编字幕、操作、音乐和键鼠声。320/430px缩放检查与正常速度整片播放分别记录；几何检查和60fps元数据不证明观众不会眩晕。
