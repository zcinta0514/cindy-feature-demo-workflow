# Cindy 功能演示工作流 · 完整制作套件 v2

把本地实际使用的组件、案例、镜头、鼠标、品牌、声音处理与源码一起带走，在同事的 Mac 上复用。默认 4:3 / 3840×2880 / 60fps。**新功能仍须检查和适配；同等效果通过基准复现和逐片验收确认，不以“安装成功”代替。**

## 安装与使用

从 [v2.0.0 发布页](https://github.com/zcinta0514/cindy-feature-demo-workflow/releases/tag/v2.0.0) 下载 `cindy-feature-demo.zip`，在 Cindy「插件 → 技能」导入。安装包保持精简；首次使用由 Cindy 自动下载并校验数百 MB 的完整资源/源码，放入新工程。发布页另有离线资源 ZIP、SHA256SUMS 与参考影片。Cindy 的单个 Skill 导入上限为 200 MB（已核对 v0.1.125 源码），所以完整资源单独分发，不要求使用者手动拆包。

整个仓库可下载/克隆作为离线工程和开发源；日常安装仍导入发布页的小 ZIP，避免把数百 MB 资源塞进受管 Skill。不要只复制 SKILL.md：安装包里的脚本、清单和参考帧都要保留。首次完整恢复及浏览器依赖建议预留至少 3 GB 磁盘空间。

新建任务发给 Cindy：

> /cindy-feature-demo 先安装并复现随包的4:3标准样片，运行检查并给我HTML和视频对照。通过后，为【功能】制作一条演示，用【具体任务】展示用途，完成中英版本和双平台文案。

只要 HTML：

> /cindy-feature-demo 复用随包成熟组件，为【功能】做可播放HTML，暂不生成视频。

Cindy 会建立独立工程、恢复制作库、检查依赖并执行任务。需要可用的 Cindy 模型连接、Python 3.9+、文件/命令权限及首次下载依赖的网络；Node 20+、FFmpeg、固定 Playwright/Chromium 由 setup 检查准备。有 Homebrew 时可补缺少的 Node/FFmpeg，否则说明具体缺项。主要支持 Mac。

## 工作流

功能事实核对 → 任务与结构化脚本 → 从成熟案例复用/补齐原生组件 → HTML 操作重演 → 镜头、鼠标、字幕和音频 → 中英逐帧影片 → 检查、双平台文案与本地归档。

画面先完整概览，重点才推进；组件/作品完整取景，倍率按目标计算，大鼠标与页面等比变换，关键操作时镜头落稳；减少无意义停顿。新片默认 4:3，旧案例中的 16:9 只是历史配置。

资源按摘要去重压缩，使用时自动恢复原目录。浏览入口见 [案例目录](library/catalog.json)，具体命令和限制见 [复现说明](references/reproduction.md)。

## 与作者本地的区别

核心可复用实现已带入；作者账号、私人记录、自动任务和发送状态不共享。依赖在接收方首次安装，交付默认放新工程的 deliveries。历史渲染缓存和旧 MP4 不全部复制，保留可复用源码/资源，当前基准参考影片在 Release。新功能重建时需按固定产品锁文件准备开发依赖；历史入口不代表本版全部重新出片验收。

本版已完成88.37秒标准样片、52张源页面对照、完整4K60音视频及双语协作回放。[本版验证记录](verification/README.md) 分开说明资源完整性、基准操作/像素对比、4K60 输出与技术检查。源页面与恢复页面对比在同一 Mac 的隔离工程完成，不能冒充同事电脑验收，也不能保证任意新片无需检查就达到相同质量。

## 开发与打包

```sh
python3 tests/test_package.py
python3 scripts/package.py --output dist
```

不要提交接收方的账号配置、生成工程、node_modules 或生产记录。大 ZIP 在 GitHub Release 发布，仓库中的 vendor 分片由恢复脚本自动拼接并验 SHA256。
